# InferRef 0.12.1

Release candidate — 2026-11-13 · TestPyPI test build

InferRef 0.12.1 adds a structured Agent repair evaluation surface and tightens
alignment preflight and batch behavior. It is additive over 0.12.0: existing
traces, testcases, adapters and artifacts remain readable.

This build is published to TestPyPI for verification. It is not yet published to
PyPI or tagged as a GitHub Release.

## Install the TestPyPI build

Python 3.10 or newer is required.

```bash
python -m pip install \
  --index-url https://test.pypi.org/simple/ \
  --extra-index-url https://pypi.org/simple \
  inferref==0.12.1
```

PyPI publication is a separate maintainer decision and has not run. Use the
TestPyPI package only for release verification.

A published GitHub Release will also carry `inferref-cpp-0.12.1.tar.gz` for the
header-only C++ SDK and `inferref-skill-0.12.1.tar.gz` for the Agent skill, plus
`SHA256SUMS`. The Python package does not install the C++ headers or the skill.

## Highlights

### Structured Agent repair evaluation

`inferref agent evaluate` now supports three deterministic repair benchmarks:

- `rope_sign`
- `nf4_block_scale_offset`
- `kv_cache_index_stride`

Each benchmark has a visible case and hidden holdouts. The evaluator records
protected-path and repository integrity, a sealed MCP audit, final patches,
visible/holdout outcomes, and per-Agent model-request evidence.

`--diagnostic-mode status_only` is available for controlled comparisons. It
returns PASS/FAIL, artifact names, output role names and execution status while
removing tensor metrics, element coordinates, shapes and execution logs. The
original unsanitized response is still audited.

Codex can use an isolated local gateway with `--codex-config` and
`--codex-model`; the JSON config is converted to Codex `-c` overrides without a
shell, and only the override keys enter the public argv policy. Claude keeps
using `--claude-settings` and `--claude-model`.

### Safer alignment preflight

- Quantized and per-contract requirements are checked against the extracted
  testcase before launching an adapter.
- An executor `unsupported` result without an `output` key is handled without a
  `KeyError`.
- Prepared runs no longer leave empty run directories.
- Batch alignment preserves sequential stop semantics when a testcase-aware
  preflight rejects a candidate.
- Scaffolded runtime bridges support `--batch-manifest` and `RunBridgeBatch`.

### Data and evidence correctness

- `inferref_context` reports the real dtype for non-float inputs, including
  uint8 NF4 codes and int32 group sizes/indices.
- `status_only` includes output role names without exposing metrics or
  coordinates.
- The Agent argv policy binds `diagnostic_mode`, so full and status-only runs
  have distinct policy digests.
- The new benchmark tasks describe the input/output contract without revealing
  the seeded defect.

## Compatibility

- Trace IR `0.1`/`1.0`, `.irtensor` formats 1/2, testcase versions `0.1`–`0.4`
  and Engine Adapter `0.2` are wire-compatible with 0.12.0.
- Existing Python, CLI and C++ adapter workflows do not require data migration.
- New Agent CLI options are additive; callers that do not use them keep the
  existing behavior.
- The package still has only `numpy` as a core runtime dependency. Agent
  evaluation requires the optional `agent` dependencies; PyTorch remains
  optional.

## Known limitations

- The Agent benchmarks are evaluation tooling, not a claim that a particular
  model or diagnostic mode improves repair success.
- `status_only` still exposes MCP tool names and artifact names. A true
  `no-InferRef` comparison requires a separate runner.
- Real-model results remain development evidence unless the formal attestation
  path is used.
- TestPyPI is a staging index and may lag or differ from PyPI. Do not treat it
  as the final package source.
- This release candidate has no PyPI or GitHub Release yet; do not publish a tag
  from the TestPyPI step alone.

## Validation

The local release gate covers the Python test suite, distribution metadata and
install checks, the C++ suite, and the documented platform gates. Branch CI and
tag qualification are still required before publishing the GitHub Release or
PyPI artifacts.
