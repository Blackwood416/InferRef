# InferRef 0.11.0rc1

This is a **prerelease**, not a production-stability or hardware-coverage claim.

## Highlights

- QA fixes for trace comparison, adapter-aware Alignment planning, the Agent
  quickstart, and Suite unsupported/failure accounting.
- Native E4M3FN/E5M2 storage and software decoding; packed INT4/UINT4 Python/C++
  codecs with exhaustive byte-pattern and cross-language checks.
- Explicit affine INT8/INT4/UINT4 and NF4 descriptors, reference arithmetic,
  parameter extraction, preflight, comparison domains and cache identity.
- Pinned bitsandbytes 0.50.1 QuantState import, including one level of compressed
  scale statistics and explicit float16/bfloat16/float32 source rounding.

## Evidence and scope

The supplied local Qwen3-0.6B NF4 checkpoint's 196 weight tensors (440,401,920
elements) and all reconstructed scales matched actual bitsandbytes CPU decoding
exactly. The checkpoint stayed read-only and its SHA-256 was unchanged.

Actual CPU `Linear4bit` was checked on q_proj, k_proj, gate_proj and down_proj
with input shapes `[1,K]`, `[4,K]` and `[2,3,K]`. All 12 comparisons passed at
atol=rtol=0.002; the largest observed absolute error was 0.00006103515625.
The independent numpy reference includes the explicit pre-GEMM float16 weight
cast used by this bnb path. It is not the separate float32-weight W4A16 contract.

All four representative weights passed relocated testcase validation, Agent,
Suite and Alignment. Injected output errors and changed scales were detected;
plan/run agreed; source changes invalidated existing Alignment evidence. CI
repeats the runtime and portable workflow checks using generated weights, with
required runtime tests forbidden from silently skipping.

**Not qualified:** whole-model text generation, GPU execution, vendor fused
low-bit kernels, optional AVX512-specific repacking, arbitrary bnb versions,
deeper nested quantization or C++ execution of quantized testcases. Support for
an artifact format is not proof that every inference engine can execute it.

## Compatibility and migration

- Plain writer defaults are retained. Quantized traces require **1.0** and
  quantized testcases require **0.4**; older readers reject those versions.
- Packed INT4/UINT4 require tensor format **2**. Byte-addressable types remain
  format **1**. FP8 uses new dtype codes within format 1.
- Quantized adapters must declare explicit scheme/granularity features. C++
  tensor readers support packed types, but C++ testcase readers reject 0.4.
- Suite run reports use **0.3**: `counts.failed` excludes unsupported-only
  policy rejection. Use `counts.rejected` or `accepted` for policy gates.
- The old 0.48.2 flat host importer remains separate from the new 0.50.1 object
  bridge. Expanded scales are canonical float32 parameters, not preserved nested
  compressed storage. Source rounding and GEMM compute rounding are distinct.

Wheel/sdist assets are attached only after branch and tag qualification passes.
PyPI publication is not part of this release. Detailed contracts and historical
local evidence are in the [quantization specification](../spec/InferRef_Quantization.md).
