# InferRef 0.12.0

This release ships the P0 infrastructure milestones **M1–M3**: native C++
consumption of quantized testcases, execution-grade low-bit hardware contracts,
and hierarchical whole-model alignment with batch execution. M4 (multi-bug Agent
benchmark and `--diagnostic-mode`) is P1 and is deferred to 0.12.x.

## Highlights

- **C++ testcase `0.4` and quantization parameter ABI.** `Testcase::Load` reads
  `0.1`–`0.4`, exposes `QuantizationSpec` and the referenced
  scale/zero-point/codebook payloads to native adapters, and dequantizes
  `affine-int8/v1`, `affine-int4/v1`, `affine-uint4/v1` and `nf4/v1`
  bit-for-bit with the Python reference.
- **Runtime bridge and scaffolder.** `DebugInvokeEx`/`RunBridge(const Testcase&)`
  let an adapter query quantization metadata; a legacy two-argument bridge
  rejects a `0.4` testcase with `kBridgeUnsupportedQuantization` instead of
  ignoring scales. Scaffolded `0.4` projects compile and derive their adapter
  features from the testcase requirements.
- **Hardware contracts.** `linear/affine-int8-bias/v1`,
  `linear/affine-w4a16-bf16/v1`, `linear/nf4-w4a16-bf16/v1`,
  `swiglu/mlp/v1`, `attention/sdpa-gqa/v1` and `linear/w8a8-int32-accum/v1`
  (exact int32 accumulation, float32 epilogue, no bias in v1).
- **W8A8 preflight.** The `quantization/w8a8-int32-accum/v1` adapter feature is
  merged into derived requirements and checked before any engine launch, so an
  adapter that declares the contract but omits the token fails closed.
- **Hierarchical alignment.** `compile_step_trace` records whole-step, per-layer,
  sub-block and leaf-projection regions as nested serialized boundaries;
  serial-prefix binary search isolates a faulty layer within the documented
  evaluation bound; `--batch-manifest` runs ordered candidates in one bridge
  process; `AlignmentRunner.run(limit=K)` batches when the adapter declares
  `batch_execution` and otherwise falls back to sequential execution.

Shipped in 0.12.0 (P0 release gate):

| Milestone | Content |
| --- | --- |
| M1 | C++ testcase `0.4` reader, quantization parameter ABI, fail-closed validation, bit-exact Python/C++ goldens |
| M2 | bias/bf16/SwiGLU/SDPA contracts, W8A8 int32 accumulation, feature tokens, shared-preflight fail-closed fix |
| M3 | hierarchical step trace with nested regions, serial-prefix binary-search narrowing, C++ batch manifest, executor/`AlignmentRunner` batch with explicit fallback |

Deferred:

| Milestone | Reason |
| --- | --- |
| M4 — multi-bug Agent benchmark (`nf4_block_scale_offset`, `kv_cache_index_stride`) and `inferref agent evaluate --diagnostic-mode` | P1; scheduled for 0.12.x |

interception of third-party quantized tensors, a web viewer, and any change to
`.irtensor` or Trace IR wire layouts.

## Compatibility

- `.irtensor` formats `1`/`2`, Trace IR `0.1`/`1.0`, testcase versions `0.1`–`0.4`
  and Engine Adapter `0.2` are wire-compatible with 0.11.0. The 0.12 changes are
  additive: new contract IDs and new capability tokens.
- The C++ testcase reader now accepts `0.4`. A native adapter that only
  implements the legacy two-argument bridge must keep rejecting quantized
  testcases; the bridge returns `kBridgeUnsupportedQuantization` (`4`) with a
  diagnostic rather than dropping quantization metadata.
- `linear/affine-w4a16/v1` and `linear/nf4-w4a16/v1` remain float16-activation
  contracts. bfloat16 activations/outputs need
  `linear/affine-w4a16-bf16/v1` or `linear/nf4-w4a16-bf16/v1`; the bf16
  contracts apply exactly one nearest-even output conversion.
- `linear/w8a8-int32-accum/v1` is an integer-dot-product contract, not
  `linear/affine-int8/v1` (which dequantizes the weight first). It has no bias
  in v1, rejects rank > 2 inputs, and rejects int32 accumulation overflow.
- Adapters must declare every contract feature they implement. An adapter that
  declares W8A8 but omits `quantization/w8a8-int32-accum/v1` — including one
  with no per-contract capability entry — is now rejected during preflight
  instead of inheriting adapter-wide capabilities.
- Batch execution is opt-in and only used for `K > 1`. One process emits every
  item's artifacts, so an adapter's per-testcase timeout and artifact budget
  apply per item; `execute_adapter_batch` accepts an explicit batch timeout.

## Known limits

- **Serial-prefix narrowing only.** The binary-search evaluation bound assumes a
  runner that fails a serial prefix of a failing chain
  ([SPEC §7.2](../spec/InferRef_0.12_Core_Infrastructure.md)). With a
  containment-only runner, which fails only the exact faulty child region, a
  passing midpoint is not a valid prefix bound; the bound must not be
  generalized beyond that assumption.
- **M4 is P1 and deferred to 0.12.x.** The multi-bug Agent benchmark and
  `--diagnostic-mode` are not part of 0.12.0.
- **Linux and remote CI were not run.** WSL is disabled on the release host and
  GitHub is unreachable, so no Linux, CircleCI or GitHub Actions coverage is
  claimed for 0.12.0; the C++ code is written to be portable but its Linux build
  is unverified.
- Real Qwen3 checkpoint evidence remains optional local evidence; CI uses the
  synthetic 28-layer fixture.
- No PyPI publication, tag or GitHub Release is implied by this document.

## Upgrade notes

1. Bump `inferref` to 0.12.0. No data migration is required: existing traces,
   testcases and manifests stay readable.
2. Native C++ adapters: switch the bridge callback to `DebugInvokeEx` and read
   quantization descriptors through `testcase.HasInputQuantization()`,
   `InputQuantization()` and `QuantizationParameter()`. The legacy two-argument
   bridge keeps working for unquantized testcases only.
3. Adapters that run bfloat16 activations must advertise the new `*-bf16/v1`
   contracts; adapters that implement integer W8A8 kernels must advertise both
   `linear/w8a8-int32-accum/v1` and `quantization/w8a8-int32-accum/v1` plus the
   granularity tokens they support.
4. Adapters that accept `--batch-manifest` should advertise `batch_execution`.
   Without it, or when the command still expands `{testcase}`/`{output}` per
   launch, alignment keeps the sequential path and reports the fallback.
5. Runners used for whole-model narrowing must fail a serial prefix of a failing
   chain for the binary-search bound to hold.
