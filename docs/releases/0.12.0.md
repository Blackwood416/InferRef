# InferRef 0.12.0

Released 2026-10-22 · [GitHub Release](https://github.com/Blackwood416/InferRef/releases/tag/v0.12.0)

InferRef 0.12.0 makes quantized inference a first-class path through the
toolchain: native C++ adapters can consume quantized testcases, new execution
contracts cover bias, bfloat16 W4A16, NF4, SwiGLU, GQA attention and integer
W8A8, and whole-model alignment can narrow failures by layer and batch candidate
runs.

This is an additive release. Existing traces, testcases and Engine Adapter
manifests remain readable; new contracts and capability tokens are opt-in.

## Install

Python 3.10 or newer is required. PyPI publication has not run, so install the
wheel or source archive attached to the GitHub Release:

```bash
pip install https://github.com/Blackwood416/InferRef/releases/download/v0.12.0/inferref-0.12.0-py3-none-any.whl
```

Both `inferref-0.12.0-py3-none-any.whl` and `inferref-0.12.0.tar.gz` are attached
to the release.

## Highlights

### Quantized testcases in native C++ adapters

`Testcase::Load` now reads testcase versions `0.1`–`0.4`, including the
quantization parameter ABI. A native adapter can query scale, zero-point,
codebook and granularity metadata instead of silently treating quantized inputs
as plain tensors. `DequantizeInputToFloat32` matches the Python reference for
`affine-int8/v1`, `affine-int4/v1`, `affine-uint4/v1` and `nf4/v1` bit for bit,
with no Python or numpy dependency in the C++ reader.

The runtime bridge exposes the same information through `DebugInvokeEx` and
`RunBridge(const Testcase&)`. A legacy two-argument bridge still works for
unquantized testcases, but rejects a quantized testcase with
`kBridgeUnsupportedQuantization` rather than ignoring its scales. The adapter
scaffolder emits the new bridge and derives capabilities from testcase
requirements.

### More execution-grade contracts

0.12.0 adds contracts for the pieces that show up in real quantized models:

- `linear/affine-int8-bias/v1` — affine INT8 with bias.
- `linear/affine-w4a16-bf16/v1` and `linear/nf4-w4a16-bf16/v1` — W4A16 with
  bfloat16 activations and one nearest-even output conversion.
- `swiglu/mlp/v1` — fused SwiGLU MLP semantics.
- `attention/sdpa-gqa/v1` — grouped-query scaled dot-product attention.
- `linear/w8a8-int32-accum/v1` — INT8 × INT8 with exact INT32 accumulation,
  float32 scale epilogue, no bias in v1, and explicit overflow rejection.

Adapters must declare the features they implement. W8A8 adapters now need both
`linear/w8a8-int32-accum/v1` and `quantization/w8a8-int32-accum/v1`; preflight
fails before launch when the feature token is missing.

### Whole-model alignment at layer granularity

`compile_step_trace` records a single prefill or decode step as a nested trace:
the whole step, every decoder layer, sub-blocks such as attention and MLP, and
leaf projections. Serial-prefix binary search isolates a faulty layer within the
documented evaluation bound instead of evaluating every layer.

For adapters that support it, `--batch-manifest` runs ordered testcase candidates
in one bridge process. `AlignmentRunner.run(limit=K)` uses batch execution when
the adapter advertises `batch_execution`, and otherwise falls back to sequential
execution with an explicit diagnostic. Batch results are matched by request
order, each item writes its own artifacts, and one failing item does not abort
the remaining items.

### Safer failure behavior

The batch alignment path now applies the same quantized-comparison validation as
sequential alignment. An unevaluable comparison aborts before launch instead of
producing a false `fail`. Duplicate boundary ids no longer share run records or
output directories, and `first_failure` overrides are honored.

## Compatibility and upgrade

- Trace IR `0.1`/`1.0`, `.irtensor` formats 1/2, testcase versions `0.1`–`0.4`
  and Engine Adapter `0.2` are wire-compatible with 0.11.0. No data migration is
  required.
- Native adapters that consume quantized testcases should switch to
  `DebugInvokeEx` and read `HasInputQuantization()`, `InputQuantization()` and
  `QuantizationParameter()`.
- Adapters that run bfloat16 activations must advertise the new `*-bf16/v1`
  contracts. The existing `linear/affine-w4a16/v1` and
  `linear/nf4-w4a16/v1` contracts remain float16-activation contracts.
- Adapters that accept `--batch-manifest` should advertise `batch_execution`.
  Without it, alignment keeps the sequential path and reports the fallback.
- Runners used for whole-model narrowing must fail a serial prefix of a failing
  chain for the binary-search bound to hold.

## Known limitations

- **Serial-prefix narrowing only.** The binary-search evaluation bound assumes a
  runner that fails a serial prefix of a failing chain. A containment-only
  runner that fails only the exact faulty child region is not covered by the
  bound. See
  [SPEC §7.2](https://github.com/Blackwood416/InferRef/blob/v0.12.0/docs/spec/InferRef_0.12_Core_Infrastructure.md).
- **Agent repair benchmarks are not in this release.** The multi-bug Agent
  benchmarks and `inferref agent evaluate --diagnostic-mode` are on `main` for a
  later 0.12.x release, not in `v0.12.0`.
- **Real Qwen3 checkpoint evidence is optional local evidence.** CI uses the
  synthetic 28-layer fixture for deterministic alignment coverage.
- **PyPI is not published.** This release is distributed through GitHub Release
  assets only.
