## 5. P0 blocker: Windows lock liveness check kills pytest

File:

```text
inferref/alignment/store.py
```

Current code in `AlignmentStore._lock_is_stale()` uses:

```python
os.kill(pid, 0)
```

This is a POSIX liveness probe. It is not safe on Windows: Python implements
`os.kill()` through Windows process termination semantics. When the lock test
checks the current pytest PID, the test process terminates instead of being
probed. The Codex command is consequently reported as `aborted` with no pytest
failure output.

Reproduction:

```powershell
python -c "import pytest,sys; sys.exit(pytest.main(['-q','tests/core/test_alignment_store.py']))"
```

Observed result: process/tool `aborted`.

Control run excluding the lock test:

```powershell
python -c "import pytest,sys; sys.exit(pytest.main(['-q','tests/core/test_alignment_store.py','-k','not live_and_stale_lock_recovery']))"
```

Observed result:

```text
6 passed, 1 deselected
```

Required fix:

- keep `os.kill(pid, 0)` only on POSIX;
- on Windows use a stdlib `ctypes` implementation based on
  `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION, ...)`,
  `GetExitCodeProcess()`, `STILL_ACTIVE`, and `CloseHandle()`;
- treat `ERROR_ACCESS_DENIED` as conservatively live;
- treat an invalid/nonexistent PID as stale;
- never terminate, signal, suspend, or otherwise mutate the probed process;
- keep a foreign-host lock conservatively live;
- add a regression test proving the current PID is live and the pytest process
  remains alive after the call;
- run the full store test file after the fix, not only a `-k` subset.

Do not use `taskkill`, PowerShell process termination, or a spawned helper as a
liveness probe.

### 6.3 `inferref/alignment/store.py`

Current public surface includes:

AlignmentStore.commit_event/commit_evidence

The draft implements:

- staging-directory initialization;
- alignment directory layout;
- evidence loading;
- JSONL event sequence validation;
- same-directory atomic JSON writes;
- event replay and materialized snapshot rebuild;
- evidence artifact digest validation;
- trace/adapter drift refresh;
- lock tokens and re-entrant local lock depth.

It has not passed its complete test file because of the Windows blocker above.
After fixing it, inject failures at each transaction boundary and prove:

1. evidence file committed, event not committed;
2. evidence and event committed, snapshot not replaced;
3. snapshot replaced;
4. replay repairs case 2 without inventing or losing an event;
5. an orphan evidence file is either explicitly tolerated/quarantined or
   rejected according to one documented rule;
6. a sequence gap, duplicate sequence, missing referenced evidence, digest
   mismatch, and path escape all fail closed.

Also review whether `refresh_external_drift()` should mutate only in memory or
persist a `stale` event. Read-only load must not acquire a mutation lock or write
unexpectedly.

### 6.4 `inferref/alignment/boundaries.py`

Current public types/functions include:

```text
Boundary
BoundaryInventory / BoundaryGraph / ContainmentGraph
CausalSelection
stable_boundary_id
inventory_boundaries / build_boundary_inventory / build_boundary_graph
reverse_data_dependency
select_causal_descendants / causal_descendants
```

Implemented draft behavior:

- stable `region:<id>`, `module:<id>`, `op:<id>` IDs;
- module boundaries derived with existing `nodes_for_module()`;
- operator leaves;
- identical node-set canonicalization with `region > module > op` priority;
- containment DAG with canonical and alternate parents;
- reverse dependency from first-failure provenance;
- containment fallback with low confidence.

Known review findings not yet fixed:

1. Empty stored regions are currently included. Multiple zero-node regions
   canonicalize to the same empty node set, producing meaningless aliases and
   hierarchy. Exclude empty boundaries or reject them explicitly, and add a
   test.
2. `BoundaryInventory.to_dict()` serializes canonical boundaries but not the
   full `raw_boundaries` records. `from_dict()` therefore cannot restore alias
   names/metadata even though the class documentation says raw identities are
   retained. Either serialize `raw_boundaries` or narrow the public guarantee;
   preferred fix is a lossless round-trip.
3. Add validation in `from_dict()` for dangling alias/parent/child IDs, cycles,
   and non-minimal parent relations if serialized inventories become trusted
   artifacts.
4. Confirm an invalid first-failure `value_id` does not get reported as valid
   provenance merely because a producer field happens to parse.

### 6.5 `inferref/alignment/planner.py`

Current public types/functions include:

```text
Runnability
PlanCandidate
AlignmentPlan
boundary_requirements
plan_alignment / plan_boundaries / build_plan / recommend_boundaries
AlignmentPlanner
```

The draft is read-only and intentionally accepts either mappings or future
session objects. It reuses region recommendation and Adapter capability logic.

Review requirements:

- freeze one session-state input shape after L1 is accepted; remove unnecessary
  compatibility aliases instead of supporting many speculative shapes;
- verify all out-of-scope boundaries are excluded, not merely deprioritized;
- verify current `verified` and `unsupported` boundaries are excluded while
  `stale` boundaries remain candidates;
- when a failure exists, ensure the planner cannot select an unrelated high
  base-score region ahead of a causal immediate child unless the child is not
  runnable; the spec says to strongly prefer the narrowing frontier;
- planner runnability is estimated until a testcase is extracted and validated;
  it must not claim process-launch eligibility as a fact;
- every score adjustment must appear in `reasons`;
- tie order must remain score descending, node count ascending, stable ID;
- plan/summary output must remain bounded.
