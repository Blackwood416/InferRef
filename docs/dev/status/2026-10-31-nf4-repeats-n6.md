## 2. Corrections to the n=3 reading

The earlier n=3 summary reported Codex at 1/3. That was a small-sample result and
is superseded: adding pairs 5–7 moved Codex to 4/6. The current data does **not**
support a claim that `status_only` generally causes Codex failure. It does show
that Codex sometimes exhausts the run budget under status-only and that its
median run count is higher, while Claude's median run count is lower.

## 3. Excluded run

Pair 4 was excluded as a clean paired observation:

- Codex: `integrity_failure` after over-budget attempts.
- Claude: `infrastructure_failure` — the CLI exceeded the 900 s wall-clock limit
  during a network disturbance.

Because the pair did not produce a clean Claude measurement, it is not counted in
the n=6 table. Pairs 5–7 were collected after the gateway recovered.

Earlier network-affected status attempts from the n=3 round are documented in
the superseded snapshot and remain excluded.
