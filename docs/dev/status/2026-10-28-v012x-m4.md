## 1. Summary

M4 is implemented on local main:

- Two new blind repair benchmarks:
  - `nf4_block_scale_offset`
  - `kv_cache_index_stride`
- A generalized evaluation case schema that keeps the existing `rope_sign`
  benchmark and v0.2 manifest compatible.
- `inferref agent evaluate --diagnostic-mode {full,status_only}` threaded
  through the CLI, isolated worker, MCP server, report, and attestation.
- Deterministic fake-Agent repair and holdout tests for all three benchmarks.

The existing `rope_sign` benchmark remains green.

## 2. Implementation

### 2.1 Benchmark schema

`EvaluationBenchmark` now loads an optional `kind` (default `rope`).
`EvaluationCase` accepts a rank appropriate to that kind plus optional integer
`params`:

| Kind | Shape | Params |
| --- | --- | --- |
| `rope` | `[batch, heads, sequence, head_dim]` | none |
| `nf4_block_scale_offset` | `[rows, columns]` | `group_size` |
| `kv_cache_index_stride` | `[batch, heads, capacity, head_dim]` | `index` |

Validation is kind-specific and runs while loading the frozen manifest. Unknown
kinds, malformed params, impossible NF4 block layouts, and out-of-range KV
indices fail closed.

### 2.2 `nf4_block_scale_offset`

The host reference assigns NF4 scales by the flat logical element index
(`flat_index // group_size`), matching the existing `nf4/v1` semantics. The
candidate engine starts with a per-row scale index
(`row * blocks_per_row + column // group_size`), so later rows read the wrong
scale when a block crosses a row boundary.

- Visible: `[3, 80]`, `group_size=64`
- Holdouts: `[2, 80]`, `[4, 144]`, `[3, 96]`
- Output: `weight` float32
- Baseline: mismatch; fixed engine: visible and all holdouts pass

### 2.3 `kv_cache_index_stride`

The host reference overwrites the one-position sequence slice at `params.index`.
The candidate engine reshapes the cache as `[batch, capacity, heads, head_dim]`
before assigning the update, so it writes along the wrong logical axis whenever
there is more than one head.

- Visible: `[1, 2, 8, 4]`, `index=1`
- Holdouts: `[2, 2, 6, 3]` index 2, `[1, 4, 5, 2]` index 4,
  `[2, 2, 7, 3]` index 3
- Output: `cache_out` float32
- Baseline: mismatch; fixed engine: visible and all holdouts pass

### 2.4 Diagnostic mode

`inferref agent evaluate --diagnostic-mode {full,status_only}` defaults to
`full`.

- `full`: existing MCP responses, including comparison metrics, first-failure
  coordinates, tensor shapes, and bounded execution logs.
- `status_only`: MCP context/execution responses are reduced to PASS/FAIL,
  artifact names, output role names, and execution status. Metrics, element
  coordinates, shapes, `input_view`/`output` paths, stdout, and stderr are
  removed.
- Audit records are still generated from the original response, so tool/status
  and engine-run transitions remain valid.
- The report and attestation record `diagnostic_mode`; the isolated worker
  request carries the same mode and the parent checks that the report matches.

### 2.5 Review corrections

- `inferref_context` now reports the actual dtype of every input (`uint8` codes,
  `int32` group size/index) instead of hard-coding float32.
- The two new `TASK.md` files no longer reveal the root cause. The KV candidate
  uses a cache-layout ambiguity rather than an obvious `index - 1`; a
  single-head holdout that accidentally passed under the old bug was replaced
  with a two-head case.
- `status_only` includes output role names extracted from the comparison, with
  no metrics or coordinates.
- Per-Agent `argv_policy` now carries and hashes `diagnostic_mode`, so full and
  status-only runs have distinct policy digests.
- `AlignmentRunner` performs testcase-aware quantization and per-contract
  preflight after extraction, falls back to the prepared output directory when
  the executor returns an unsupported result without `output`, and no longer
  leaves empty prepared run directories.
- Scaffolded runtime-bridge projects parse `--batch-manifest` and call
  `RunBridgeBatch`; the skill CLI reference lists `--diagnostic-mode`.

## 4. Boundaries

- M4 is **not** in the published `v0.12.0` tag or GitHub Release. Those artifacts
  remain M1–M3 and are unchanged.
- This snapshot records the local implementation before branch CI; it has not
  been tagged or released.
- No real Codex/Claude model run was performed. CI coverage uses deterministic
  fake Agents; no autonomous repair or diagnostic-benefit claim is made.
- `status_only` changes the MCP surface only. The host retains full evidence for
  final revalidation.
- The controlled full-diagnostics vs PASS/FAIL-only ablation still requires real
  model runs and a no-InferRef arm.
