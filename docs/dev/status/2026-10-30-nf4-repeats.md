# NF4 full vs status_only repeats — 2026-10-30

- Scope: three fresh paired `nf4_block_scale_offset` evaluations per diagnostic
  mode, with Codex and Claude in every evaluation.
- Evaluator: `main` at `e812b3d` (initial matrix) and `5d3f848` (repeats); no
  evaluator code changed between them.
- Model path: both Agents through the local `magpie` gateway and the configured
  `opencode-go` DeepSeek V4.1 Flash model.
- Evidence: development reports only. No public attestation and no
  `no-InferRef` arm.

## 1. Design

Six paired evaluations:

| Pair | Run order |
| --- | --- |
| 1 | `full` then `status_only` |
| 2 | `status_only` then `full` |
| 3 | `full` then `status_only` |

Each evaluation used a fresh report directory, the same benchmark, prompt,
model, `max_engine_runs=4` budget and a clean worktree. Full and status-only
reports differ only in the MCP response surface.

## 2. Results

All twelve Agent executions produced valid sealed audits and
`repository_unchanged=true`; every report had `host_integrity_passed=true` and
`agent_model_request_satisfied=true`.

### Full mode

| Pair | Codex engine runs | Claude engine runs | Report | Holdouts |
| --- | ---: | ---: | --- | --- |
| 1 | 3 | 3 | pass | all pass |
| 2 | 3 | 4 | pass | all pass |
| 3 | 3 | 3 | pass | all pass |

### status_only mode

| Pair | Codex engine runs | Claude engine runs | Report | Detail |
| --- | ---: | ---: | --- | --- |
| 1 | 4 | 2 | pass | both Agents passed |
| 2 | 4 | 2 | fail | Codex `agent_failure`: visible case did not pass within budget; Claude passed |
| 3 | 4 actual + 1 rejected | 3 | fail | Codex `integrity_failure`: attempted a fifth run, rejected as `budget_exhausted`; Claude passed |

Wall-clock totals:

- `full`: 200.9 s, 257.5 s, 302.8 s.
- `status_only`: 583.2 s, 1119.3 s, 641.0 s.

## 3. Interpretation

- **Full mode is stable.** Both Agents passed all three pairs and needed three
  to four engine runs.
- **Claude was stable in both modes.** `status_only` needed two to three engine
  runs and passed all three pairs.
- **Codex showed a directional status_only cost.** It passed one of three
  status-only pairs; the other two exhausted the four-run budget, and one of
  those attempted a fifth run. Full mode was three for three.
- The signal is suggestive, not conclusive: n=3, one model, one machine, and
  run order was only partially balanced. A Fisher-style comparison or a claim
  that `status_only` causes failure is premature.
- Failure classifications matter: pair 2 is an `agent_failure` (no visible pass
  inside budget), while pair 3 is an `integrity_failure` caused by a rejected
  over-budget attempt, not a successful run. Neither is hidden by the host.

## 4. Excluded network-affected runs

Two earlier status-only repeats had Claude hit the 900 s wall-clock limit during
the reported network disturbance and were classified as `infrastructure_failure`
by the harness. They are excluded from the table above. After the gateway
recovered, two Claude-only status-only reruns passed in three engine runs each,
and the clean paired status-only runs above were then collected. This is why the
earlier raw directories contain more status runs than the six used here.
